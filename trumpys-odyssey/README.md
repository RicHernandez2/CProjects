# Trumpy's Odyssey

An SNES-style metroidvania collectathon, in the spirit of NES Zelda: 8 themed
worlds, each with its own 8-screen overworld and a 2-room dungeon guarded by
a boss, 101 stacking secrets with Greek-mythology names spread across every
screen, and rainbow-colored alien creatures called **Trumpys** that orbit
the player yelling "Trumpy!" when caught. Full design brief in
[`design/GAME_BIBLE.md`](design/GAME_BIBLE.md).

> **"Trumpy" is a fictional creature** — a rainbow, Alf-like alien with a
> longer/harder snout — invented for this game. Not based on any real person.

## Status

The full **8-world map is built and wired end-to-end** — every screen
exists, every screen-to-screen exit connects to a real neighboring scene,
every dungeon has a boss that drops the item gating the next world, and all
101 secrets are placed. What's still missing is real art/audio/music and
hand-tuned level design (see Roadmap) — every screen currently uses the
same placeholder-geometry entities, procedurally laid out.

### The world map

8 worlds, each an 8-screen grid (3x3 minus one corner, NES-Zelda style)
plus a 2-room dungeon reached from screen 8:

| # | World | Boss | Drops (unlocks next world) |
|---|-------|------|------------------------------|
| 1 | Verdant Hollow | Grovewarden | `fire_stick` |
| 2 | Sundered Dunes | Duneleviathan | `magic_lamp` |
| 3 | Frostspire Reaches | Rimefang | `hookshot` |
| 4 | Emberdeep Caverns | Cinderjaw | `flippers` |
| 5 | Cragstone Pass | Gorgonhide | `ice_boots` |
| 6 | Skyfallen Ruins | Aetherwing | `wing_charm` |
| 7 | Marrow Fen | Bogmother | `storm_horn` |
| 8 | Duskbloom Meadow | Nightpetal | `aegis_of_zeus` (final reward) |

You start in World 1, Screen 1. Each world's screen 8 has a cave-mouth
trigger into its dungeon (2 rooms: an entrance/enemy room, then the boss
room) and an east-edge **world gate** that only opens once you've beaten
that world's boss and picked up its item. Screen 1 of every world after
the first has a matching unconditional gate back to the previous world's
screen 8, so backtracking always works.

### What's implemented

- **All 64 overworld screens + 16 dungeon rooms**, generated by
  [`tools/generate_screens.py`](tools/generate_screens.py) — a layout
  generator (not runtime procgen; it emits real, static, inspectable
  `.tscn` files that get committed like any hand-authored scene). Re-run it
  any time the grid topology, world list, or secret distribution needs to
  change instead of hand-editing 80 files.
- **Full 101-secret dataset** (`data/secrets_101.json`), distributed one or
  two per overworld screen with no gaps or duplicates (verified: ids 1-101,
  each placed exactly once).
- **`SecretsDatabase` autoload** — tracks collected secrets, sums stacking
  bonuses per effect type, flips on **Zeus Mode** at 101/101.
- **`GameState` autoload** — now also carries the player's health/bombs/
  tunic-color across screen transitions (since `change_scene_to_file()`
  destroys and recreates the whole scene tree, including the Player, on
  every screen change), the 8 progression items, and current world/screen
  for the HUD.
- **`ScreenExit`** — the edge-of-screen transition trigger, reused for
  plain screen-to-screen exits, the dungeon entrance, and item-gated world
  gates (shows a hint and gently pushes the player back if the required
  item isn't owned yet).
- **`BossEnemy`** — same AI as regular enemies, tougher, and unlocks its
  world's progression item on death.
- **Player** — 4-directional movement, bombs, melee attack, per-damage-type
  mitigation read live from `SecretsDatabase`, tunic color shift, and now
  state that survives screen transitions.
- **Combat system, enemies, Trumpys, bombs/cracked walls, secret inventory
  UI, HUD** — see the individual scripts under `scripts/`; behavior
  unchanged from the original systems, just now deployed across the whole
  map instead of one room.

### How to run

1. Install [Godot 4.3+](https://godotengine.org/download).
2. Open `project.godot` in the editor.
3. Press F5 (runs World 1, Screen 1 — the game's actual entry point).
4. Controls: arrow keys/WASD or gamepad stick to move, Space/gamepad A to
   bomb, Enter/gamepad B to attack, I/gamepad X to open the secret
   inventory. Walk into a screen edge to move to the next screen.

No PNG/audio assets are required to run — every visual is a placeholder
`ColorRect`/primitive shape, the same trick the original Pygame prototype
(`design/reference/trumpys_odyssey_prototype_v0.1.py`) used. Real pixel art
and sound drop in later without touching the underlying systems.

## Roadmap — what's still ahead

The map is complete and playable start-to-finish; what's missing is
polish and hand-crafted texture, not structure:

1. **Real art** — the 32x32 SNES-style icons described per-secret in
   `data/secrets_101.json` (`icon_prompt` field), tile sets per world,
   character/enemy sprite sheets with directional walk animations, the
   Trumpy sprite itself. Swap into the `Sprite` `ColorRect` nodes /
   add `AnimatedSprite2D`s once art exists — the generator's per-world
   color palette (`WORLDS` list in `tools/generate_screens.py`) is a
   reasonable starting palette reference for each world's tile art.
2. **Hand-tuned level design** — every screen's obstacle/secret/enemy
   placement is procedurally scattered (deterministically seeded, so it's
   reproducible, but not hand-composed). The Bible's "two lit torches,
   cracked-tile-looks-like-a-dried-tree" detail and dungeon puzzles aren't
   art-differentiated per world yet, and dungeon Room 1 doesn't gate
   progress on clearing its enemies (it's a straight walk-through).
3. **Sound & music** — `Trumpy.gd` already has a proximity-based
   `AudioStreamPlayer2D` hook (`ProximitySound`) ready for a stream, just
   needs actual audio files.
4. **Economy** — gem pickups apply instantly on enemy death with no
   physical pickup/animation; potions, arrows, fire sticks as consumables,
   and the cave/store system from the Bible aren't built. (`fire_stick`
   etc. currently only exist as world-gate keys, not the burn-the-dried-
   tree mechanic the Bible describes.)
5. **Unused secret effect types** — `magic_power`, `magic_cost`,
   `max_mana`, `potion_potency` are collected and summed in
   `SecretsDatabase.stat_totals` but nothing reads them yet since there's
   no magic-casting or potion system to hook them into.
6. **Directional player facing** — attacks hit in a radius around the
   player rather than in the direction they're facing.
7. **Playtest recording hook** — the Bible asks for a built-in play-test
   capture to MP4; not implemented.
8. **Joystick calibration** — movement and the `bomb`/`inventory`/`attack`
   actions are wired for gamepad, but the exact button mapping in
   `project.godot` was hand-authored outside the Godot editor and hasn't
   been verified on real hardware — check Project Settings → Input Map if
   a binding doesn't respond correctly.
9. **Cross-world visibility** — the Bible calls for other worlds being
   *visible* from the starting world before you can reach them. Right now
   the gate is a plain colored wall with a hint label, not a view into the
   next world.

## Project layout

```
project.godot
data/secrets_101.json          # all 101 secrets, structured
design/                        # original Game Bible, setup guide, Pygame prototype
tools/generate_screens.py      # regenerates every world/screen/dungeon .tscn
scripts/autoload/              # GameState, SecretsDatabase, CombatSystem
scripts/world/                 # screen_root.gd (per-screen bookkeeping)
scripts/entities/               # Player, EnemyBase, BossEnemy, Trumpy, Bomb,
                                 # CrackedWall, SecretPickup, ScreenExit
scripts/effects/                 # dust, floating heal text, sparkles
scripts/ui/                     # HUD, secret inventory UI
scenes/entities/                # matching .tscn scenes (placeholder ColorRect art)
scenes/effects/, scenes/ui/
scenes/world1/ .. scenes/world8/  # 8 screens + 2 dungeon rooms each
assets/                         # empty — tiles/sprites/sounds/icons land here
```
